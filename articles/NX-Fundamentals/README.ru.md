# NX Fundamentals: основы NX для корпоративного frontend workspace

## Назначение статьи и связь с предыдущими материалами

Эта статья продолжает [NX Workspace](../NX-Workspace/README.ru.md). В ней не нужно повторять инициализацию NX, генерацию Angular-приложения или первоначальные проверки сборки, тестов и линтинга: они уже описаны в предыдущей статье.

## Предварительный план

- Исследовать реальную структуру workspace после этапа реализации `NX-Workspace+1`.
- Объяснить, как связаны проекты NX, targets, конфигурационные файлы и граф проектов.
- Рассматривать следующий архитектурный шаг только после проверки фактического состояния репозитория.
- Чётко отделять реализованное от предлагаемого.
- Добавлять ссылки на официальную документацию NX для существенных технических утверждений.

## Исходное состояние реализации

Перед написанием прочитать раздел [Состояние реализации и границы статьи](../NX-Workspace/README.ru.md#состояние-реализации-и-границы-статьи). Сейчас в репозитории есть рабочий NX Workspace, минимальное Angular-приложение и проект end-to-end тестов. Бизнес-библиотеки, доменные границы, теги проектов и автоматическое применение правил Module Boundaries пока не реализованы.

## Правило подготовки черновика

Перед добавлением команд или утверждений о существующей реализации проверять соответствующую ветку и файлы. Не повторять шаги, уже описанные в NX Workspace.
