## Параграф 5 — Facades, Signals и Effects: реактивное взаимодействие Dashboard и модальных форм

Предыдущий материал уже содержит введение в Facade Services. Поэтому в новом параграфе не начинаем эту тему заново, а переходим к практическому применению фасадов и показываем, как они организуют взаимодействие компонентов и общее состояние приложения.

### Практическая задача

В приложении Personal Finance необходимо изменить пользовательский сценарий добавления операций:

1. Формы «Добавить доход» и «Добавить расход», которые сейчас открываются как отдельные страницы, преобразовать в диалоговые модальные окна.
2. Пользователь открывает соответствующее модальное окно непосредственно с Dashboard.
3. После заполнения формы и нажатия OK новая транзакция сохраняется.
4. Модальное окно закрывается, а Dashboard автоматически отображает актуальные данные без перезагрузки страницы и ручного обновления.

### Архитектурный фокус

Dashboard и диалоговые окна не должны напрямую управлять внутренним состоянием друг друга. Они взаимодействуют с общей функциональной Facade, которая инкапсулирует состояние и операции с транзакциями.

После успешного добавления дохода или расхода Facade обновляет состояние. Dashboard получает актуальные значения через Signals. В этом сценарии необходимо также рассмотреть Angular `effect()`: объяснить его назначение и показать обоснованное применение в контексте взаимодействия реактивного состояния с императивным API или внешним механизмом, если выбранная реализация действительно этого требует.

Важно не использовать Effect искусственно для вычисления производных значений или для простой передачи состояния между Signals. Для производных данных по-прежнему предназначен `computed()`. В параграфе нужно чётко показать границы применения `computed()` и `effect()` на конкретном примере.

### Что раскрываем в параграфе

- практическая роль Facade Services в сценарии с Dashboard и модальными формами;
- взаимодействие компонентов через общую Facade без прямой связи друг с другом;
- преобразование отдельных страниц добавления дохода и расхода в диалоговые модальные окна;
- обработка подтверждения OK и закрытие диалога;
- обновление общего состояния транзакций через Facade;
- автоматическое обновление Dashboard посредством Signals;
- назначение Angular `effect()`, его ограничения и обоснованный сценарий применения;
- различия между `computed()` и `effect()` на практике.

Центральная демонстрация параграфа — полный пользовательский сценарий: открытие модального окна с Dashboard, добавление транзакции, подтверждение OK, обновление состояния через Facade и автоматическое отображение новых данных на Dashboard.
