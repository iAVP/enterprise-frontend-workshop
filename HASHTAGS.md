# Hashtag Guidelines

This document defines the controlled hashtag vocabulary for the **Enterprise Frontend Workshop**.

The goal is to keep publications recognizable, technically relevant, and aligned with the workshop's professional positioning.

Hashtags should describe the actual content of a publication. They are not a substitute for meaningful technical content or a clear professional profile.

## 1. Core Hashtags

Use these hashtags to identify publications belonging to the workshop.

- `#EnterpriseFrontend` — the identity of the series and its main technical focus
- `#SoftwareArchitecture` — architecture, modularity, boundaries, and design decisions
- `#FrontendEngineering` — engineering practices for maintainable frontend applications

**Usage rules:**

- Include `#EnterpriseFrontend` when a publication belongs to this series.
- Select one or two additional core hashtags when relevant.
- Do not automatically add all three to every publication.

## 2. Agentic Engineering and AI-Native Software Development

This category covers the evolution of software engineering through AI coding agents, agentic workflows, and AI-native development practices.

The workshop emphasizes engineering discipline, architectural quality, maintainability, and verifiable outcomes — not merely faster code generation.

### 2.1 Agentic Engineering

Use these hashtags when discussing software development workflows in which coding agents perform or support engineering tasks under appropriate human supervision.

- `#AgenticEngineering`
- `#CodingAgents`
- `#AINativeEngineering`
- `#AIassistedDevelopment`
- `#SoftwareEngineering`

Relevant topics include:

- AI-assisted requirements analysis and task decomposition
- Specification-driven and plan-driven development
- Agent-assisted implementation, refactoring, and debugging
- Automated testing, code review, and quality verification
- Context engineering and effective use of coding agents
- Human-in-the-loop workflows and engineering accountability
- Architecture and maintainability in AI-assisted development

### 2.2 Agentic AI Engineering

Use these hashtags when the publication focuses on designing, implementing, integrating, or operating AI agent systems.

- `#AgenticAI`
- `#AIAgents`
- `#AIEngineering`
- `#LLMEngineering`
- `#MCP`

Relevant topics include:

- Tool calling and external system integration
- Agent orchestration and multi-agent workflows
- Model Context Protocol (MCP)
- Context, memory, and state management
- Evaluation, observability, reliability, and security
- Enterprise integration and production readiness

### 2.3 AI-Assisted Engineering Practices

These topics may overlap with Agentic Engineering but can also apply to workflows that use AI without autonomous or multi-step agents.

Relevant topics include:

- Code generation and assisted implementation
- Refactoring and legacy code analysis
- Test generation and test improvement
- Code review and documentation
- Architecture analysis and technical decision support
- Developer productivity and quality assurance

Use the following hashtags when they accurately describe the publication:

- `#AIassistedDevelopment`
- `#AIEngineering`
- `#SoftwareDevelopment`

### 2.4 Usage Rules

- Use `#AgenticEngineering` for agent-driven software development practices.
- Use `#AgenticAI` for engineering AI agent systems.
- Use `#AIEngineering` for broader AI engineering topics or when the two areas overlap.
- Use `#CodingAgents` for practical work with AI coding tools and agents.
- Use `#MCP` only when Model Context Protocol is substantively discussed.
- Use `#AINativeEngineering` when AI is integrated into the engineering workflow as a core working approach, rather than used occasionally as an assistant.
- Use `#AIassistedDevelopment` for AI-supported development workflows, whether or not they involve agents.

Do not imply that a project uses autonomous agents, multi-agent orchestration, or production AI systems unless the content supports that claim.

## 4. Russian-Language Publications

For Russian adaptations published in the **Around IT** VK community, use Russian hashtags where they fit the audience and subject.

- `#РазработкаПО`
- `#АрхитектураПО`
- `#Фронтенд`
- `#Программирование`

For publications about agentic development, use established English technical terms where they are more recognizable and precise, for example:

- `#AgenticEngineering`
- `#CodingAgents`
- `#AIEngineering`

English technology names and hashtags may be retained in Russian-language publications.

Do not automatically add all Russian and English variants to the same publication. Choose the combination that best fits the specific post and audience.

## 5. Publication Rules

1. Prefer **3–5 relevant hashtags per publication**. Use fewer when sufficient.
2. Include `#EnterpriseFrontend` when the publication belongs to this series.
3. Choose technical and AI-related hashtags based on the actual content.
4. Use consistent spelling and capitalization.
5. Avoid generic, promotional, or unrelated hashtags.
6. Do not invent new project-specific hashtags for individual posts without a clear reason.
7. Do not use AI-related hashtags merely because an AI tool was used incidentally while preparing the publication.
8. Review this vocabulary when the workshop introduces a genuinely new technical topic.

## 6. Platform Guidance

### LinkedIn

Combine the workshop identity with a small selection of relevant technical or engineering hashtags.

For professional positioning, use terms such as Agentic Engineering, AI Engineering, Enterprise Architecture, and Software Architecture in the actual post text when the content supports them. Hashtags alone are not a substitute for describing relevant experience and engineering outcomes.

### Xing

Prioritize professional relevance, technical precision, and readability. Use the same controlled vocabulary as LinkedIn where appropriate.

### VK / Around IT

Combine Russian-language hashtags with established English technology hashtags where appropriate. Preserve technical terms when translation would make them less recognizable.

The language of the publication does not require translating established technology names or their hashtags.

## 8. Maintenance and Governance

This file is the single source of truth for the workshop's hashtag vocabulary.

New hashtags should be introduced deliberately, based on recurring technical themes or a meaningful change in the workshop's scope.

The vocabulary should remain small enough to be consistent and broad enough to represent the workshop's actual engineering topics.

**Guiding principle:** Use hashtags to make substantive engineering work discoverable. Let the technical content demonstrate the expertise.
